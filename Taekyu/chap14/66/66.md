## 풀이

- 토핑을 의미하는 배열이 주어지는데, 여기서 이 배열을 잘라서, 각 부분배열에 들어있는 원소의 종류의 갯수가 같도록 자르는 방법의 수를 반환
- 만약 방법이 없으면 0을 반환

* 걍 다 잘라보면서 확인해보는 방법밖에 없지 않나싶다

### 66-a

- 시간 초과 실패가 너무 많이 뜸

* 다음은 GPT가 분석한 원인임
  원인: 알고리즘이 사실상 O(n²) 이라서요.

매 칸 i에서 자를 때마다
topping.slice(0, i) 와 topping.slice(i)가 매번 새 배열을 복사합니다 → 각 자르기마다 O(n).

그 복사본 두 개로 new Set(...)을 만들어 서로 다른 토핑 수를 다시 전부 세죠 → 각 자르기마다 또 O(n).

이게 i=1부터 n-1까지 반복 → 전체가 O(n²) + 엄청난 메모리 할당/GC까지 덤.

입력 상한이 n=1,000,000이라 이 방식은 시간(그리고 메모리)적으로 절대 통과 못 합니다.

### 교재 정답

- 배열을 나눠서 각각 다른 배열로 구분하지 않음
  - 그대신 다른 객체 하나를 더 선언해서, 거기가 동생이 먹을 토핑 종류와 갯수를 관리해줌
  * 그러면서 객체의 프로퍼티 갯수를 동생이 먹을 토핑 갯수, 따로 Set으로 관리하는 데이터를 형이 먹을 토핑 갯수로 관리하여 비교해준다
