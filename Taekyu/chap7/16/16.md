# 문제 분석

## 입력

- 기능은 진도가 100%일때 반영
- 뒤의 기능이 앞의 기능보다 먼저 개발되는 경우, 앞 기능이 배포될때 함께 배포되어야함

* 현재 작업 진도가 적힌 정수 배열 progresses
* 각 작업의 개발 속도가 적힌 정수 배열 speeds

## 출력

- 각 배포마다 몇 개의 기능이 배포되는지 배열로 반환

## 풀이 생각

- 일단, 각 작업별로 완료일을 알아내야할것같음 -> 배열형태

  - 예를들어 첫번째 입출력 예의 경우, [7, 3, 9]

  * 일단은 배열의 첫 인덱스 요소부터 push하면서, front의 데이터보다 더 큰 데이터가 rear에 들어올때까지 계속해서 push함 (front의 데이터보다 더 작은애들까지만 하나의 배치로 처리하고, 더 크면 어차피 다음 배치에 처리되므로)
  * 만약 더 큰 데이터가 들어오는 경우, 큐의 그때까지의 데이터(더 큰 데이터가 들어오기 이전)갯수를 세고, 큐를 비워줌
  * 이 갯수를 회차별 작업의 갯수를 세는 배열에 push해줌 -> 각 배포마다 몇 개의 기능이 배포되는지 알 수 있다

## 문제 수행 결과

- 정확성 테스트에서 2개 오답
- 틀리는 입력

  ```
  // 예시 1:
  const progresses = [99, 99];
  const speeds = [ 1, 1];
  // leftDurationArray = [1, 1]
  // 둘 다 1일 후에 완료 → 한 번에 [2]가 되어야 하지만…

  // 예시 2 (가장 단순화):
  const progresses = [90, 50];
  const speeds = [ 1, 50];
  // leftDurationArray = [10, 1]
  // 둘 다 10일째 한 번에 배포 → [2]가 되어야 하지만…

  ```

## 2번째 시도

- 로직을 아예 수정하여 남은 작업일 배열인 leftDurationArray의 인덱스의 요소가 큐의 front의 요소보다 작거나 같은 경우에 큐에다 push하는 구조로 변경함
- 그리고 마지막 요소까지 해당 if문 로직에 걸리게 하기위해 leftDurationArray에다 매우 큰 수인 Infinity를 추가함 -> 이렇게 해야 마지막 순회에서 무조건 else분기 쪽으로 빠져서 큐의 길이만큼을 returnArray에 push하고 정상적으로 순회를 종료할수있기때문
