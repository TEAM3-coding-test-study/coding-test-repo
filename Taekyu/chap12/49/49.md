# 문제 분석

## 입력

- k : 유저의 현재 피로도
- dungeons : 각 던전별 최소 필요 피로도와 소모 피로도가 담긴 2차원 배열

## 출력

- 유저가 탐험할 수 있는 최대 던전 수 반환

## 풀이

- 백트랙킹 챕터니까 아마 재귀를 활용한 백트랙킹이 정석적인 정답이라 생각하지만, 다른 방법이 없나 고민해보았다
  - 내가 생각할때 최대로 많은 던전을 돌아야한다면, 던전을 선택할때 현재 피로도로 가능한 던전 중 소모 피로도가 최소가 되는 곳부터 돌면되지 않을까?
  * 근데 그렇게 하는 경우 계산된 피로도로 다른 던전을 돌지 못하는 경우가 생기므로 최대 던전 수를 돌지는 못하겠다는 생각도 든다

* 그냥 답안을 보았다.
  - 백트랙킹에서 재귀를 자꾸 쓰는데, 내가 재귀에 익숙하지 않아서 로직을 잘 구현을 못하는것같다

## 정답

- 재귀 함수인 dfs를 처음 봤을때도 이해가 잘 안됐다

  - 계속 보다보니 나름의 이해를 한 것 같은데, 그것을 여기다 정리하겠다

- 우선 처음 dfs를 호출할 때 초기 피로도, count = 0, dungeons와 visited를 인자로 해서 한다
  - dfs에서는 던전의 갯수만큼 반복문을 돌면서 로직을 수행
  - 현재 피로도가 i번째 던전의 최소 피로도보다 크면서, 아직 방문하지 않은 던전일때만 로직을 수행한다
  - 해당 던전을 방문했다고 업데이트하고, 다시 cnt를 1올리고, 현재 피로도를 갱신해서 dfs를 재귀 호출한다
    - dfs가 리턴된 후에는 다시 방문을 0으로 되돌림 -> 이는 왜냐하면 재귀에서 리턴되었다는 것은 해당 방문을 취소하고 다른 경우의 수를 찾는다는 의미이기 때문
  * 반복문을 돌면서 재귀호출을 하기 때문에 모든 방문 경우의 수를 다 따져보면서 조건에 맞지 않는 경우에는 백트랙킹을 하고 다음 순회로 넘어갈 수 있음
