# 문제 분석

## 입력

- 이용자 id가 담긴 문자열 배열 id_list
- 각 이용자가 신고한 이용자의 ID 정보가 담긴 문자열 배열 report (report의 원소는 "이용자ID 신고한ID" 형태의 문자열)
- 정지기준이 되는 신고 횟수 k <- k번 이상 신고당한 사용자는 게시판 이용이 정지되고, 해당 유저를 신고한 사용자는 메일을 받게됨

## 출력

- 각 유저별로 처리 결과 메일을 받은 횟수를 배열에 담아 반환

## 풀이

- 필요한 자료구조
  - 사용자별 신고횟수를 담는 자료구조
    ```js
    {
        frodo: 0,
        muzi: 1,
        ...
    }
    ```
    - 값이 k 이상이라면, 해당 유저를 신고한 유저에게 메일이 발송되어야하므로 이 "신고자"를 추적해야됨
    * 동일한 유저에 대한 신고는 하나로 카운팅 -> 그럼 신고자를 key로 쓰는거 어떨까?
  * 개선
  ```js
  {
      muzi : {
          frodo: 0,
          neo: 1,
          apeach: 1,
      },
      neo: {
          frodo: 2,
          muzi: 1,
          apeach: 3
      }
  }
  ```
  - 위와같은 자료구조를 운용해서, report의 값을 전부 처리하고 난 이후, 객체의 값을 순회하면서 값이 k보다 클 때 카운팅을 하면 될듯
  * 진행하다보니 위와같은 자료구조로는 부족함
    - 왜냐하면 위의 자료구조로는, 어떤 피신고자가 정지된자인지 구분할 수 없기 때문
    * "muzi frodo" 인 경우, muzi의 데이터만 업데이트해주는것 뿐만아니라, 다른 이용자의 경우도 frodo가 존재하는 경우, 카운팅을 올려줘야할듯

## 24-a

```
{ muzi: { frodo: 1 }, frodo: {}, apeach: {}, neo: {} }
{ muzi: { frodo: 2 }, frodo: {}, apeach: { frodo: 1 }, neo: {} }
```

위와같이 새로운 신고사실이 추가될때, 이전의 기록이 새로 추가되는 기록에 반영되지 않는 문제가 있음
-> 따라서 24-b로 개선

## 24-b

```js
{
  muzi: [ 'frodo', 'neo' ],
  frodo: [ 'neo' ],
  apeach: [ 'frodo', 'muzi' ],
  neo: []
}
{ muzi: 1, frodo: 2, apeach: 0, neo: 2 }
```

위와같이 신고자와 피신고자를 매핑하는 객체와 피신고자의 피신고횟수를 기록하는 객체를 나눠서 운용

- 문제점

```
{ con: {}, ryan: { con: true } }
{ con: {}, ryan: { con: true } }
{ con: {}, ryan: { con: true } }
{ con: {}, ryan: { con: true } }
{ con: {}, ryan: { con: true } }
{ con: 4, ryan: 0 }
[ 0, 1 ]
```

이렇게 신고자가 동일한 경우에도 피신고횟수가 올라가는 문제점이 있음

## 24-c

```js
{
  muzi: { frodo: true, neo: true },
  frodo: { neo: true },
  apeach: { frodo: true, muzi: true },
  neo: {}
}
{
  muzi: { apeach: true },
  frodo: { muzi: true, apeach: true },
  apeach: {},
  neo: { frodo: true, muzi: true }
}
```

- 위와같이 신고자와 피신고자를 매핑하는 객체, 그리고 피신고자를 key로하여 신고자를 매핑하는 객체 2개로 운용함
- 이렇개해야 피신고 횟수가 k번 이상인 사용자를 식별할수있고, 그러한 피신고자를 신고했던 신고자도 식별이 가능해짐

## 교재

- 교재에서는 {피신고자 : [신고자a, 신고자 b]} 와 같은 객체와 사용자별 결과통보메일 수신횟수를 저장하는 객체를 운용함

* 한 유저가 같은 피신고자를 여러번 신고했을때의 중복 처리 문제는 Set()을 이용
