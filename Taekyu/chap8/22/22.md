# 문제 분석

## 입력

- 채팅방 들어오고 나간 기록 + 닉변 기록이 담긴 배열 문자열 배열 record

## 출력

- 모든 기록 처리 후 최종적으로 관리자가 보는 메시지를 문자열 배열 형태로 반환

## 풀이

- 일단 "닉네임"과 "id"라는 프로퍼티는 구분되어야함 <- 왜냐면 닉네임을 변경하더라도 사용자를 구분할수있어야하기때문
- 그러면 이런식은 어떨까 {아이디 : 닉네임} 식으로 매핑된 객체를 해시로 사용하는거임

* 일단 입력으로 들어온 문자열 배열의 요소인 한 문자열을 띄어쓰기로 자름

  - 0 번째 요소를 기준으로 명령어 처리를 구분
  - Enter나 Leave인 경우 id와 매핑된 값을 표시
  - Change인 경우 2번째 요소 값으로 1번째 요소(id)와 매핑된 값을 변경해줌

* 22-a의 문제점

  - 템플릿 리터럴을 쓰더라도 어차피 문자열로 저장되기 때문에 추후 표현식의 값이 바뀌어도 이것이 문자열에 적용되지 않는다

* 개선책

  - 그냥 문자열이 아니라 값으로 저장하고 있다가, 최종적으로 해시에 저장된 값으로 대치하는 방식을 써야할듯싶다!

  * 즉 일단 배열에 push할 때는 닉네임이 아닌 id로 저장하고, 추후에 닉네임으로 대치하면 될듯?

* 22-b
  - record를 순회하면서 빈 칸을 기준으로 스트링을 나누고, 나눠진 배열을 processCmd에 넘겨줌
  - 채팅배열을 의미하는 chatScreen과 유저 id와 닉네임을 매핑하는 객체인 userInfo, 그리고 문자열을 쪼개서 저장한 배열을 인자로 받는 processCmd
    - arr의 가장 첫 부분이 명령의 종류를 의미하므로, 그것을 기준으로 switch문으로 분기처리
    - Enter나 Change인 경우 유저 등록 정보가 갱신되어야 할 필요가 있으므로 그 처리를 해준다
    ```
    userInfo[arr[1]] = arr[2];
    ```
    - 채팅창에 이제 문자열(채팅)을 집어넣는데, 이때 중요한 점은 최종결과에서는 최종 닉네임이 표시되어야하므로, 변동되는 값인 nickname이 아닌 id를 넣어주는것이다. 이떄 최종적으로는 문자열에서 id부분과 나머지를 분리해서 id를 닉네임으로 변환시켜줄것이기 때문에 /를 구분자로 넣어준다
  - 순회를 끝내고 나서는 이제 chatScreen을 순회하면서, userInfo를 참조하여 id를 닉네임으로 변환해준다
