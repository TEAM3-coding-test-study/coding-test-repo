# 문제 분석

## 입력

- phone_book : 전화번호부에 담긴 전화번호를 담은 문자열 배열

## 출력

- 어떤 번호가 다른 번호의 접두어이면 false, 그렇지 않으면 true를 반환

## 풀이

- phone_book 배열에서 가장 큰 문자열의 길이와 가장 작은 문자열의 길이를 구한다 -> 이것은 추후 순회할떄 필요함
- 반복문을 돌리는데, phone_book의 각 원소에 대해서 substr을 통해 앞부분부터 자른 문자열을 Set에 추가시킨다
  - 이때 만약에 집합의 크기가 기존 배열인 phone_book의 크기와 달라지는 경우 이는 어떤 원소가 어떤 원소의 접두사로 포함되어서 중복이 발생했기 때문에 Set의 크기가 phone_book 배열의 크기보다 줄어든것

* 이러한 순회를 min부터 max까지 phone_book의 모든 원소에 대해 돌려주게되면 접두사의 포함여부를 알수있다

### 채점결과

- 정확성 테스트에서 2개 나가리, 효율성도 2개 나가리가 난다

### 원인 도출 및 개선

- 정확성에서는 왜 틀리는건지 잘 모르겠다
  - 그런데 아마 효율성에서는 이중 반복문을 썼기 때문에 걸리는듯하다

* GPT에 물어보니 다음과같은 테스트케이스에서 실패한다고한다

  `const phone_book = ["456", "1234", "1235"];`

  - 내 알고리즘은 현재 앞에서부터 같은 길이만큼 끊어서 비교하기 때문에, 접두사관계가 아닌 1234와 1235도 접두사 관계로 취급되는 문제가 있다

  * 알고리즘을 수정해서, 순회를 돌면서 substr을 할 때, 배열 원소의 크기만큼만 자르도록 해야될것같다
    - 예를 들면 위의 배열에서는 가능한 원소의 길이는 3, 4이므로 3번 4번만 substr을 하면된다
      => 근데 이 방식으로도 위의 문제는 해결불가능함
      => 왜냐면 예를들어서 456때문에 3으로 substr하게되면 123, 123이 중복되기 때문임
      => 걍 책을 봤다

## 교재

- 내 코드는 접두사 포함여부를 비교할 때 접두사의 사이즈를 구하는데 난점이 있었는데, 책에서는 접두어를 쉽게 찾기위해 정렬을 사용했다
  - 정렬을하면 어떤 문자열의 접두사가 될 수 있는 문자열을 무조건 바로 앞쪽에 위치하게된다
